## 0. 一句话说清两套 H3 通道

| | 通道 A:manxue / 1ren 直连 | 通道 B:RunningHub 导演台 |
|---|---|---|
| 本质 | MiniMax H3 **模型** API(OpenAI 兼容,`/v1/video/generations`) | H3 **ComfyUI 导演工作流**(RunningHub GPU 实例) |
| 段间衔接 | ❌ 每段独立生成,零像素继承(根因所在) | ✅ 首尾帧 fl2v 锚定 + 工作流内建 `continuityEnabled` 拼接 |
| 出片 | 单段 MP4(5.17/10.13/15.08s),自带立体声 | 多段时间轴 → **一个 ComfyUI 任务 → 一个成品 MP4** |
| 密钥 | 1ren key(余额 $4,够不到 Seedance) | `RUNNINGHUB_ENTERPRISE_API_KEY`(hypit 企业账 98350 分) |
| 计费 | 直连,不走网关账本 | 走 `video.generate/h3` 路由,60 分/段,有预扣/审计 |

**用户判断"短剧带货主要走 H3"= 走通道 B。通道 A 没有段间帧入口,治不了衔接;通道 B 才是治根因的腿。**

## 1. 输入契约(client 实际提交的东西)

`submit_h3_director` 把本地图片/视频上传到 RH 拿 fileName,拼成 `nodeInfoList` 提交。核心字段:

```
node 12 (MiniMaxH3Director):
  timeline_data   ← 完整时间轴 JSON(下面 §2)
  task_type       ← "fl2v — 首尾帧生视频(First-Last Frame)" 等
  global_prompt   ← 全片级提示词
  cfg / seed / frame_rate / width / height
  ref_max_size / total_frames
  steps(默认20) / sampler(res_multistep) / scheduler(simple)
  shift_video(12) / shift_audio(3)
```

- 画面:竖版默认 576×1024(9:16),24fps,每 5s ≈ 124 帧
- 工作流选择:`r2v/v2v/rv2v` → ref2va UNET 工作流;`t2v/i2v/fl2v` → fl2va UNET 工作流
- **只吃本地文件**:CDN 公网 URL 会炸成 FileNotFoundError(提交前必须落地)

## 2. timeline_data 结构(client 生成)

```jsonc
{
  "version": 5,
  "editMode": "segment",
  "totalFrames": 总帧数,
  "frameRate": 24,
  "video": { ...顶层源视频, v2v/rv2v 才填 },
  "global": {
    "taskType": "fl2v — 首尾帧生视频(First-Last Frame)",
    "prompt": global_prompt,
    "refs": [],
    "referenceVideo": {...},
    "continuousReference": false,   // 写死 False
    "genImage": {...}
  },
  "output": {
    "mode": "fixed",
    "aspectRatio": "3:4 (竖版标准)",
    "megapixels": 0.4,
    "multiple": 32,
    "width": 576, "height": 1024,
    "maxExportFrames": 0,
    "exportMode": "all",            // 导出全部段
    "audioMode": "generate",        // H3 多模态原生出声
    "continuityEnabled": false,     // ★ 段间连续性开关,client 写死 False
    "continuityOverlapFrames": 9    // ★ 段间重叠 9 帧 = 0.375s
  },
  "runSelectEnabled": false,
  "runSelection": [],               // 逐段"跑不跑"
  "fillStrategy": "cache",
  "segments": [                     // ★ 可以放任意多段
    {
      "id": "msdxxxx", "start": 0, "length": 124, "frameCount": 124,
      "durationSec": 5,
      "prompt": "本段镜头描述…", "negativePrompt": "bad video",
      "isStartFrame": true, "isEndFrame": true,
      "genImage":  {imageFile, width, height},   // 首帧
      "endImage":  {imageFile, width, height},   // 尾帧
      "taskType": "",                            // 段级可覆盖任务类型
      "refs": [],                                // 参考图 1-9
      // 可选: referenceVideo / refVideos(1-3) / refAudios(1-3)
      "selected": true
    }
  ],
  "keyframes": [每段派生 _s/_e 两个关键帧],
  "durationSec": 总秒数,
  "shots": [每段派生一个 shot]
}
```

**关键:`segments` 是数组,一次提交可带全部 7 段 → 一个 ComfyUI 任务 → 工作流内完成"生成+拼接",出片是一个完整 MP4(时长 = 各段之和)。** 这就是导演台"自己带拼接功能"的含义。

## 3. 六种任务模式(段级 taskType 可混用)

| 模式 | 输入 | 段内行为 | 适短剧场景 |
|---|---|---|---|
| `t2v` | 纯 prompt | 自由生成 | 转场空镜、氛围段 |
| `i2v` | 1 张首帧 | 首帧定构图,自由推镜 | 场景板驱动的单镜头 |
| `fl2v` | 首帧+尾帧 | 首尾两帧**锚定**,中间自由生成 | **段间衔接主力** |
| `r2v` | 2-9 张参考图 | 参考主体一致性 | 产品/角色不跑偏 |
| `v2v` | 参考视频 | 视频转视频 | 复刻动作 |
| `rv2v` | 参考视频+参考图 | 动作照原片、主体换新 | 换主体复刻 |

## 4. fl2v 实测行为(验证段抽帧,重要)

验证段:SH-1-01-01(黑发三视图角色板)→ SH-1-01-02(金发+字幕"被嫌气色差28天后"角色板),6.58s。抽 3 帧:

- **帧 0**:完整保留首图构图(三视图+特写分栏)
- **中间帧**:H3 **自由生成**了一个新场景(办公室工位,米色西装女性站着看手机)——首尾帧里都没有的画面
- **末帧**:保留尾图构图,并**渲染了尾图里的字幕**(红字,但文字轻微变形:"字幕被嫌气色差 28 天后"→ 出片里"字幕被嫌 气色差 28天后"排版乱)

**结论(必须记住):**

1. ✅ fl2v 是"**首尾锚定 + 中间自由生成**",不是关键帧插值。段边界那一帧像素锁死(段 N 尾图 = 段 N+1 首图 ⇒ 拼接点严丝合缝),但**两段接近边界的内容是各自独立生成的**,拼接处运动方向可能不连贯。
2. ✅ 首帧是**角色板** → 出片保持"三视图展示板"样式;首帧是**场景镜头板** → 出片是场景镜头。**05_shots/frames 36 张是角色板/场景板混装,喂之前必须分清楚。**
3. ✅ 图里烧进的字幕/文案会被 H3 渲染进视频,但**文字质量差(变形/排版乱)** → 清晰品名、卖点字幕仍要后期叠字,别指望 H3 出。
4. ⚠️ 角色一致性弱:验证段里头发色从黑漂成金、裙变裤、脸变老。要锁人物,得靠 `refs` 参考图(r2v 通道)或全程统一的角色三视图板。
5. ✅ 音频 `audioMode=generate`:H3 多模态原生出立体声(环境音/动作音),但**不是台词口播**——带货台词/口播仍要后期 TTS + 混音。

## 5. 内建拼接与段间连续性

- `output.exportMode="all"`:一次任务导出全部段为一个成品 MP4(不需要 ffmpeg 再拼)
- `output.continuityEnabled`:段间连续性开关。**client 目前写死 False**(h3_director_client.py:335),没暴露成参数
- `output.continuityOverlapFrames=9`:开 continuity 时段间重叠 9 帧(0.375s)做过渡
- `runSelectEnabled + runSelection`:可只跑时间轴里的某几段
- ⚠️ `continuityEnabled=True` 的确切行为(重叠溶解 or 硬拼)没测过,要开它得改 client 一行(把 False 放开成参数),再用 2 段小任务验证

**当前策略下的段间衔接方案(不改代码也能用):**
段 N 的 `endImage` = 段 N+1 的 `startImage`(同一张图喂两次)→ 拼接点像素级锁死。这是比 1ren 通道"零继承"强一级的**尾帧继承链**。更进一步:段 N 出片后用 ffmpeg 抽**实际末帧**,喂给段 N+1 的 startImage → 连运动方向都对齐(串行跑,段间等出片)。

## 7. 根因对照:为什么 1ren 出的 7 段"段段衔接不上"

| 层 | 1ren 通道 A(已跑,被拒) | 导演台通道 B |
|---|---|---|
| 段间 | 每段独立生成,零像素继承 | 尾帧继承链:拼接点像素锁死 |
| 拼接 | 只能 ffmpeg concat/xfade 淡化硬边 | 工作流内建一个成品 MP4 |
| 声音 | 段内 H3 出声,段间无声缝 | 同上,但段间过渡帧内嵌 |

**xfade 治的是"硬边",治不了"画面本身不连续"。尾帧继承链治的正是后者。**

## 7.5 ★ 2 段 fl2v 验证段实测(2026-10-05, 两轮共 240 分)

**第一轮(taskId=2106563340543508481, 喂三栏拼图板,判定:失败不可用)**

设计:段 1 = SH-1-02-01(面试官场景板)→ SH-1-05-03(递软糖场景板),段 2 = SH-1-05-03 → SH-1-02-01,
段 1 尾图 = 段 2 首图(同一张,像素锁死),一次 submit 带 2 段。

**实测结论(推翻/确认上表 ⚠️/❓ 项):**

1. ✅ **内建拼接确认**:2 段一个 timeline → 结果回 **1 个 MP4**(时长 10.33s ≈ 2×5s),不是 2 个独立 MP4。
   导演台出片就是"完整成片",**不需要 ffmpeg 再拼**。
2. ✅ **首尾锚定确认**:帧 0 = 段 1 首帧(面试官场景板原样),帧 9.8s = 段 2 尾帧(面试官场景板原样)。
   场景板驱动下场景稳定,没有漂成"灰底角色展示"。
3. ✅ **拼接点像素锁死**:4.8s(段 1 尾)与 5.2s(段 2 首)两帧画面严丝合缝(同一个人、同一个动作、
   同一个粉扑特写),验证"段 N 尾图 = 段 N+1 首图 ⇒ 拼接点无跳变"。
4. ✅ **音频原生出片**:1 条 AAC 立体声轨(H3 多模态自带环境声),576×1024 @ 24fps。
5. ⚠️ **角色板三栏结构会被继承**:场景板本身是"上中下三栏拼图"(每栏一个镜头),H3 把三栏
   **当成一个画面**保留进视频(三栏全在场)。这不是 bug,是"喂进去什么构图就出什么构图"——
   要单镜头出片,就得喂**单镜头单画面**的分镜图,不是三栏拼图板。
6. ⚠️ 角色一致性仍弱:段 1 面试官与段 2 面试官是同一人(场景板驱动下),但发型细节、面部微漂。
   要锁人物,refs 参考图通道(r2v)仍是正解。

**对 7 段全片的直接推论:**
- 拼接方案从"7 段 + ffmpeg"升级为"**一次 submit 7 段 → 1 个 45s 完整 MP4**"(GPU 费按总时长,约 3-5 元)
- 但 7 段同任务任一段炸全炸 ⇒ 落地时拆成 **2+2+2+1 共 4 个任务**,段间用"上段尾帧=下段首帧"锁死,
  再 ffmpeg 拼接(4 个 MP4,各 10-20s),风险隔离
- **前置条件不变:分镜图必须是"单镜头单画面",不能是 05_shots 现在的"三栏拼图板"** → 出图 20 张单镜头板

**第二轮(taskId=2106567937419706370, 裁单栏 736×437/438,判定:机制全通,画面可用)**

设计:段 1 首帧=面试官顶栏裁切, 尾帧=林夏底栏裁切;段 2 首帧=林夏底栏裁切(像素锁死), 尾帧=面试官顶栏裁切。

实测逐帧:
1. ✅ 首帧锚定准:面试官深灰西装/金表/婚戒/面试桌全保留,冷白调
2. ✅ 拼接点像素锁死:4.8s(段1尾)与 5.2s(段2首)林夏特写严丝合缝,同一人同一动作
3. ✅ 尾帧锚定准:全片尾帧软糖特写暖光逆光,产品 payoff 出来了
4. ✅ 单镜头干净:画面不再是三栏拼图,是正常单镜头视频
5. ⚠️ 中间段自由生成漂了:段 2 中间 7.5s 出了一段**无人空走廊**(林夏举软糖动作没在中间段兑现)
   → 工艺约束:关键动作/台词画面要落在**首尾锚帧**,中间段 H3 自由发挥会漂
6. ⚠️ 裁切单栏比例偏宽(736×437 ≈ 5:3),H3 自动补到 576×1024 竖屏,上下留白/模糊填充,构图可用但非满屏

**裁切 vs 重出原生单镜头板**:裁切版画面可用,但偏宽裁切 + 中间段漂移 ⇒ 正式 7 段全片建议走 B(重出 20 张原生单镜头分镜板,160 分),构图满屏 + 关键动作写进首尾锚帧描述,减少中间段漂移。
