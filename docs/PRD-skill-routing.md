# PRD：需求→技能 自动路由（intent-based skill routing）

状态：设计定稿（P0 待落地）｜日期：2026-10-01｜负责人：产品
决策已锁：① 路由纪律进 `AGENTS.md`、元数据契约进 `skill-creator` 模板；② 低置信**必问**；③ 评测集进 `docs/routing-eval.md`。

## 1. 问题
客户不选技能、只描述需求 → agent 要挑对 skill。现状是 `AGENTS.md` 里硬编码一张小路由表（weeksir/omni/super-clone/hypit），skill 一多就维护不动，且依赖人肉 `/` 选。目标：**说人话就能命中，且持续加 skill 时路由不用重写**。

## 2. 目标 / 非目标
- 目标：① 客户说需求 → 命中正确 skill；② 歧义/低置信 → **一句**澄清；③ 无匹配 → 明说不做；④ **随 skill 增长零改路由代码**（改的是 skill 自己的元数据）。
- 非目标：不做重型分类器/训练；不改 DSH 内核；客户界面不暴露 skill 技术菜单。

## 3. 三层路由（按需升级，当前只做 L1）
- **L1 描述驱动（现在·唯一要做）**：路由能力下沉到每个 `SKILL.md` 的 `whenToUse` + 用户原话例句 + `whenNot` 反例。agent 上下文里本就看得见全目录，靠语义匹配挑。`AGENTS.md` 只留"路由纪律"（怎么判、歧义怎么办），**不留具体 skill 表**。→ 加 skill = 填好元数据，路由自动覆盖。
- **L2 Router 元技能（skill 十几个后）**：一个 `router` skill 读索引 → 输出 `{选中skill, 置信度, 理由}` → 交回主流程。集中、可测。触发升级条件：L1 命中率下降 / skill 数 >~15。
- **L3 意图分类器（上百再说）**：embedding/关键词分类。当前个位数，**不做**（过度工程）。

## 4. Skill 元数据契约（路由准不准的地基）
`skill-creator` 模板强制每个 `SKILL.md` frontmatter 带：
- `name`
- `description`：一句话"做什么"
- `whenToUse`：触发场景 + **3-5 条用户原话例句**（路由的匹配语料）
- `whenNot`：明确不接什么（防误路由，尤其相邻 skill 边界）
- `inputs`：需要客户给什么（缺了 agent 追问）
- `examples`：正/反各若干
**规则**：加 skill 时必须把路由语料喂进 `whenToUse`，并在 `docs/routing-eval.md` 补 ≥2 条该 skill 的测试说法。这是"持续补 skill"与"路由准"能同时成立的唯一办法。

## 5. 路由决策协议（agent 行为，写进 AGENTS.md）
1. 读客户意图 → 对全目录 `whenToUse` 语义匹配。
2. **高置信单一命中** → 直接加载该 skill 执行，**不反问"你要哪个技能"**。
3. **多候选 / 低置信** → **必问**：只问**一个**澄清问题，列 2-3 个候选 + 各一句区别，客户点一下即定。（决策②：视频生成烧额度，路由错了代价大，宁可问不可猜。）
4. **无匹配** → 明说"本阶段没有对应能力"，**绝不编 skill 名 / 不假装会做**（沿用 AGENTS.md 现纪律）。
5. 尊重账号绑定与客户包可见性（客户包只暴露该露的 skill）。

## 6. 与现有 UI 的关系
- 客户侧：隐藏 `/` 技术菜单和 super-clone 下拉（已定"客户只说话"），路由纯在 agent 侧。
- 运维/开发侧：保留 `/` 手动选（调试用）。
- 待修：super-clone-ui"选中不自动填 prompt"的 bug（若走 UI 选才相关；纯 agent 路由不受影响）。

## 7. 可观测 & 回归
- 每次路由（意图→skill→置信→是否追问）追加进 `accounts/<acct>/SKILL_LOG.md`，攒真实语料反哺 whenToUse 例句。
- **路由评测集** `docs/routing-eval.md`：每条 = 一句典型客户说法 → 期望 skill（+ 期望"追问"的歧义样例）。**每加/改一个 skill 跑一遍**，防把老的带偏（回归）。

## 8. 分期
- **P0（现在·纯文档）**：① `AGENTS.md` 加"路由纪律"节（协议 §5）；② `skill-creator` 模板补元数据契约（§4）；③ 建 `docs/routing-eval.md` 种子集（现有 skill 各 2-3 条 + 2-3 条歧义样例）。
- **P1**：router 元技能（L2）+ 澄清话术模板 + SKILL_LOG 路由字段规范化。
- **P2（远期）**：量大再评估 L3 分类器。

## 9. 验收标准
- 客户不选技能、只说需求，现有每个 skill 的评测说法命中率 ≥ 目标（P0 先人工跑通）。
- 歧义说法触发"一个"澄清问题、不错选。
- 加一个新 skill 后：只需填它的 SKILL.md 元数据 + 评测集补 2 条，**不改 AGENTS.md 路由表**即可被正确路由（证明零维护扩展成立）。
