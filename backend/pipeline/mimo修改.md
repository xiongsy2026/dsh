产品规则必须重写

当前最危险的是：

原视频中旧产品可见 → "产品" 填用户的新产品名称。

这会直接污染 source_storyboard。

应该变成：

【产品解析规则】

- 只描述原视频中实际可见的原商品。
- 不接收、不知道、不引用任何目标新产品名称或目标产品图片。
- 当前 Shot 原商品可见：
  "产品"填写对原商品的客观可见描述。
  例如："白色按压泵瓶"、"黑色长裤"、"透明塑料包装食品"。
- 无法确认具体类别时，只写可确认的外观类别，不得猜品牌、型号、材质或性能。
- 当前 Shot 原商品不可见：
  "产品"="无"
  "产品动作"="无"
- 不得在原本无商品的 Shot 中补商品。

Step 1.5 再负责：

原商品描述
↓
product_name / product_images
↓
目标商品

这才是正确链路。

营销功能 要处理，否则逻辑冲突

你一开始禁止：

营销判断

但 JSON 又要求：

"营销功能": "此镜头或口播在证明商品的什么卖点"

这必然诱导 MiMo 推测：

显瘦、舒适、耐用、防水、效果好……

建议为了不改现有 Schema，保留字段名，但重新定义语义：

【商品交互.营销功能】

该字段名称虽然为“营销功能”，但禁止推断商品卖点或效果。

只允许根据当前镜头直接可观察的展示行为填写以下客观类型之一：

- 外观展示
- 结构展示
- 操作演示
- 使用过程
- 状态变化
- 尺寸/数量展示
- 前后结果对比
- 包装展示
- 无

不得填写：
显瘦、舒适、透气、防水、耐用、好吃、高级、提升效果等推断性卖点。

这样 Step 1.5 仍然可以利用它判断：

原镜头的“功能槽位”是什么，

但不会继承 A 商品的虚假卖点。

Shot 切分建议彻底简化

你现在最不应该保留的就是 scene_cut / action_grained。

现在冻结工作流已经明确：

Shot 数量和镜头时长以原视频真实镜头结构为准，不人为拆分合并。

MiMo System Prompt 应直接规定：

【Shot 切分规则】

1. 以原视频真实镜头边界为第一依据：
   - 硬切
   - 明确转场
   - 镜头重新建立
   - 明显独立镜头切换

2. 同一个连续镜头内部，即使人物执行多个连续动作，
   默认仍属于同一个 Shot。

3. 不得仅因为：
   - 一句话结束
   - 一次手部动作结束
   - 产品姿态发生变化
   - 人物转身
   而人为创建新的 Shot。

4. 不得为了控制 Shot 时长而拆分或合并。

5. Shot 数量完全服从原视频真实结构。

如果一个连续 5 秒镜头里：

拿起 → 打开 → 展示 → 放下

那就在同一个：

"人物动作": "右手拿起产品，随后双手打开并向镜头展示，最后放回桌面"

不要人为切 4 个 Shot。

时间规则也应该极度简化

当前 Prompt 里：

target duration
compression duration
15/20/25/30
一帧误差

全部混在一起了。

Step 1 只需要：

【时间规则】

- 输入视频为 Step 0 已裁剪完成的 trimmed video。
- 时间坐标只针对当前输入视频。
- 第一帧时间为 00:00.00。
- 所有 Shot 时间使用 0 → target_duration 的局部时间轴。
- 不知道原始长视频中的 trim_start，也不得自行恢复原始视频绝对时间。
- target_duration 由后端提供，是唯一权威时长，不得修改。
- MiMo 只负责识别 Shot 边界。
- 允许原始识别产生极小舍入误差；最终 snap 和时间规范化由后端 Checkpoint A 完成。

尤其不要再要求 MiMo：

“最后一镜必须自己强行等于目标时长”。

更准确的是：

尽可能客观识别，Checkpoint A 负责 canonicalize。
