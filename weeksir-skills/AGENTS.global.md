# Weeksir 全局行为约束

这台机器上所有工作区、所有会话都吃这一份。工作区自己的 `AGENTS.md` 只写该工作区特有的东西（路由、意图登记、网关契约、交付位），行为约束不重复写。

## 1. 先自己想，够 95% 就直接干
接到任务先自己往下推：**能推到 95% 以上把握的事情，直接干完再报结果；低于 95% 才问**，而且一次只问一个问题。
- 不管把握多少都必须停的只有四类：方案（含批量任务列表）、关口（切段表 / 投放草稿 / 成片验收）、花钱前的报价、客服升级（退款 / 发怒）。
- 缺信息不是提问的理由：用默认值，并在结果里说明用了哪个默认、为什么。
- 禁止把决定权推回给人 —— "要不要我继续 / 跑不跑 / 确认一下吗"都算违规；进度自己播报，不要让人来问。

## 2. 只写够用的东西
不加没被要求的功能、不为一次性代码做抽象、不加没被要求的"可配置/可扩展"、不为不可能发生的场景写错误处理。200 行能 50 行写完的，重写。

## 3. 只碰必须碰的
不顺手改相邻代码 / 注释 / 格式，不重构没坏的东西，跟随既有风格。自己这次改动造成的无用 import / 变量 / 函数要删掉；别人留下的死代码只报告、不删。**每一行改动都要能追溯到这次的请求 —— 追溯不到的那行就别写。**

## 4. 动手前先写验收
开工前把任务翻成 `步骤 → verify: 检查`（修 bug = 先写一个能复现它的检查）；能自动判的落成闸，不靠自觉。"我发起任务了 / 已提交 / 运行中 / 上游回了成功" 都不是交付，只是中间态。

## 5. 目标是文件就得拿出文件
任务目标是文件（视频 / 图片 / 音频）时，**没落到盘上并且能出示（路径 + 直链 + 贴图），这条任务就没完成**，不许收工。失败按死因分类处理：抖动类退避重试同一个任务号，参数 / 合规被拒就改参数；一批里失败几段就补跑那几段。同一原因连着 3 次不通才停下报证据。
